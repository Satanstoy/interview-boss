# TDD 开发计划

**功能名称:** 修复单条面经重新分析时聚类流水顺序问题
**日期:** 2026-05-10
**TDD 状态:** 🔴 红灯阶段准备

## 需求描述

单条面经重新分析时，`cluster_batch` 中旧 QB 条目的清理（`_cleanup_old_sources_txn_v2`）发生在聚类之后，导致旧数据参与聚类决策。应改为：先清理旧贡献，再加载剩余 QB，再聚类。

## 问题根因

`cluster_batch` (`pipeline.py:185`) 的执行顺序：
1. 加载新 `questions_detail` ✓
2. 加载已有 `question_bank` ← 包含旧条目
3. 合并聚类 ← 旧条目干扰决策
4. `_atomic_write` 中才清理旧条目 ← 太晚了

正确顺序应为：
1. 加载新 `questions_detail`
2. **先清理当前批次 URL 的旧 QB 贡献**
3. 加载清理后的 `question_bank`
4. 合并聚类
5. 写入新聚类

## 验收标准

- [ ] 重新分析单条面经时，旧 QB 条目在聚类前被清理
- [ ] 聚类上下文只包含清理后的 QB + 新 tagged 数据
- [ ] 共享多 URL 的 QB 条目只移除当前 URL 的贡献，其他 URL 保留
- [ ] 独占 URL 的 QB 条目被完全删除
- [ ] AI 答案在清理后仍能恢复到新聚类
- [ ] 全量重建（build）流程不受影响
