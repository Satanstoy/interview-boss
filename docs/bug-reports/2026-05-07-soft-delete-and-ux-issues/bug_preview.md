# Bug 预览报告

**日期:** 2026-05-07
**问题:** 批量删除硬删除风险 + 前端导入缺少类型/季节选择 + 脏数据清理 + LLM 配置修改问题
**严重程度:** High

## 初步诊断

### 问题 1：question_bank 批量删除使用硬删除

**问题现象:** 题库中的题目被删除后无法恢复，数据永久丢失。

**根本原因:** `master_bank.py` 中的删除操作（单条删除第 805 行、批量删除第 842 行、重建题库第 314 行）使用 `DELETE FROM` 物理删除，而 `question_bank` 表没有 `deleted_at` 字段支持软删除。相比之下，`jd`、`interview`、`questions_detail` 表已经支持软删除。

**影响范围:**
- **功能:** 题库管理、批量删除、题库重建
- **用户:** 所有用户（特别是管理员）
- **数据:** 数据完整性风险，误删无法恢复

### 问题 2：前端导入缺少类型选择和招聘季节选择

**问题现象:** 用户在"导入"页面无法选择导入的是 JD 还是面经，也无法选择招聘季节。系统依赖后端 AI 自动判断类型，季节取自全局设置。

**根本原因:** `StagingPanel.vue` 组件没有提供类型选择和季节选择的 UI 控件。类型完全依赖后端 AI 解析，季节硬编码取自 `props.activeSeason`。

**影响范围:**
- **功能:** 数据导入
- **用户:** 所有用户
- **数据:** 可能导致数据分类不准确

### 问题 3：job_positions 表存在脏数据

**问题现象:** 用户设置中的"目标岗位"下拉列表显示测试数据，如 `AAAAAAAAAAA...`、`test@#$%!`、`测试岗位ABC`、`测试开发`。

**根本原因:** 之前测试留下的脏数据未清理，`job_positions` 表中存在无效记录。

**影响范围:**
- **功能:** 用户设置、岗位选择
- **用户:** 所有用户
- **数据:** 数据质量问题

### 问题 4：question_bank 表 cat1 字段存在脏数据

**问题现象:** 题库分类中存在 `test` 等测试分类。

**根本原因:** 测试数据未清理。

**影响范围:**
- **功能:** 题库分类筛选
- **用户:** 所有用户
- **数据:** 数据质量问题

### 问题 5：用户个人 LLM 配置修改问题

**问题现象:** 用户反馈个人 LLM 配置一旦保存之后就不支持修改。

**根本原因:** 需要进一步检查。从代码看，`SettingsPanel.vue` 中的 `startEditMyLLM` 和 `saveMyLLM` 函数逻辑正确，API 端 `PUT /api/profile/llm` 也支持更新操作。可能是前端状态管理问题或 API 调用失败未正确提示。

**影响范围:**
- **功能:** 用户 LLM 配置管理
- **用户:** 所有普通用户
- **数据:** 无直接影响
