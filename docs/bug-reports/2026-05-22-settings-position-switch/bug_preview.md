# Bug 预览报告

**日期:** 2026-05-22
**问题:** 设置面板岗位切换存在三个交互 bug：即时生效、双重刷新、状态回退
**严重程度:** High

## 初步诊断

### 问题现象

1. **BUG-001 (即时生效)**：用户在设置面板点击目标岗位按钮时，后端数据库**立即被修改**，而不是等到用户点击"保存全局配置"按钮后才生效。用户每点一次岗位按钮，就触发一次 API 请求并显示 toast "已切换到岗位：XXX"。
2. **BUG-002 (双重刷新)**：用户点击"保存全局配置"后，页面数据被刷新两次（视觉表现为页面闪烁/跳动）。原因是 `position-changed` 事件和 `@close` 事件**都触发了 `loadAllData()`**。
3. **BUG-003 (状态回退)**：从岗位 A 切到 B，再切回 A，点保存后，实际生效的岗位却是 B。根因是 HTTP GET 缓存（30s TTL）导致 `fetchPublicProfile()` 返回**旧岗位的缓存数据**。

### 根本原因

| Bug | 核心原因 |
|-----|---------|
| BUG-001 | `onSwitchPosition()` 在按钮点击时立即调用 `switchPosition()` / `switchMyPosition()` API，而非仅更新本地状态 |
| BUG-002 | App.vue 中 `onSettingsClose` 和 `onPositionChanged` **都调用** `loadAllData()`，造成重复请求 |
| BUG-003 | `http.js` 的 GET 缓存（30s TTL）在 `PUT` 请求后未被清除，`loadProfile()` 读到的是缓存中的旧位置数据 |

### 影响范围

- **功能:** 岗位切换、分类体系加载、全局配置保存
- **用户:** 所有用户（管理员和普通用户均受影响）
- **数据:** 不影响数据完整性（数据库最终状态正确，但前端展示与实际不一致）

## 风险评估

| 风险类型 | 等级 | 说明 |
|---------|------|------|
| 功能中断 | High | 用户无法正确切换岗位，操作结果与预期不符 |
| 数据完整性 | Low | 数据库最终状态正确，但中间过程产生了不必要的 API 调用 |
| 安全风险 | Low | 无安全风险 |
| 用户体验 | High | 即时生效 + 双重刷新 + 状态回退严重影响操作可信度 |
