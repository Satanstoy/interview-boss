# Bug 预览报告

**日期:** 2026-05-10
**问题:** 增量聚类不稳定导致频率与来源数量不匹配，聚类质量退化
**严重程度:** Critical

## 初步诊断

### 问题现象
1. 总题库中 11/247 条记录的 frequency 与实际唯一来源 URL 数不一致
2. 32 条记录的 sources 包含已被软删除的面经 URL，频率虚增
3. 增量匹配只看顶层 question 文本，不看 original_questions，导致聚类越来越不准确
4. 频率计算存储在数据库中但不区分用户和题库模式，公共用户看到的频率包含个人来源
5. "重建题库"按钮暴露在高频使用的题库页面，容易误触发消耗大量 token

### 根本原因
多个相互关联的缺陷共同导致聚类质量退化：
- 增量匹配上下文不足（只传顶层 question，不传 original_questions）
- 匹配后不回写 original_questions，聚类"遗忘"新合并的题目变体
- sources 中残留已删除面经的 URL，未清理
- frequency 存储时计算正确，但查询时不按 bank_mode 过滤，导致不同模式下频率不准确
- 频率计算依赖 sources 数组长度，但 sources 中仍有重复 URL（去重 key 曾用 url+company+round）

### 影响范围
- **功能:** 题库排序（按频率排序结果不准确）、来源详情展示、聚类匹配准确率
- **用户:** 所有用户（频率显示不准），管理员（聚类质量退化需频繁重建）
- **数据:** 32 条 QB 记录含过期来源，11 条记录频率虚增

## 风险评估

| 风险类型 | 等级 | 说明 |
|---------|------|------|
| 功能中断 | Medium | 频率排序不准但不影响核心功能 |
| 数据完整性 | High | sources 残留已删除 URL、频率不匹配 |
| 安全风险 | Low | 无安全风险 |
| 聚类退化 | High | 增量匹配越来越不准确，需频繁重建 |
