# Bug 预览报告

**日期:** 2026-05-10
**问题:** 题目分析功能存在四个系统性问题：不支持断点续传、界面切换后无后台反馈、分析中不显示详细内容、软删除记录污染聚类质量
**严重程度:** High

---

## 初步诊断

### 问题现象

用户点击面经"分析"按钮后：

1. **断点续传缺失：** 若分析过程中网络中断或页面刷新，所有 LLM 计算（标注 + 聚类匹配）从零重来，造成时间浪费和 API 额度浪费。
2. **切换界面无后台反馈：** 分析进行中切换到其他 Tab，后台 SSE 仍在运行，但用户完全没有反馈，无法感知分析状态，甚至误以为分析已中断。
3. **分析过程不显示详细内容：** 进度仅显示"标注中"/"聚类中"/"保存中"三个标签，用户看不到正在处理哪道题、匹配了多少题、打标结果是什么。
4. **软删除记录污染聚类：** `interview.py:53-56` 加载 `question_bank` 时未过滤 `deleted_at IS NULL`，导致已软删除的题目参与增量匹配，影响聚类准确性。

### 根本原因

#### BUG-001: 不支持断点续传
- **位置:** `backend/app/routers/interview.py:132-200`
- **根因:** SSE `event_stream()` 函数是纯内存计算，没有在任何阶段将中间结果持久化到数据库。标签化结果（`tagged_rows`）和匹配结果（`match_result`）仅存在于单次请求的协程栈中，连接断开即丢失。

#### BUG-002: 切换界面无后台反馈
- **位置:** `frontend/src/App.vue:960-979`, `frontend/src/App.vue:308`（`v-if="activeTab === 'Interview'"`）
- **根因:** `DataTable` 组件被 `v-if` 条件渲染，切换到其他 Tab 时组件销毁。虽然 SSE 连接仍在运行，但用户没有任何全局进度指示器。分析完成后，`toast.success` 仍然会显示，但分析期间用户处于信息盲区。

#### BUG-003: 分析中不显示详细内容
- **位置:** `backend/app/routers/interview.py:140-184`, `frontend/src/App.vue:329`
- **根因:** SSE 事件仅包含 `step` 和 `message` 两个字段，没有携带题目级别详情（如每道题的标签结果、匹配到的聚类 ID、匹配/新增的具体题目列表）。前端仅展示步骤标签文本，没有设计详细进度面板。

#### BUG-004: 软删除记录污染聚类
- **位置:** `backend/app/routers/interview.py:53-56`
- **根因:** 加载已有 `question_bank` 进行增量匹配时，SQL 查询缺少 `AND deleted_at IS NULL` 条件：
  ```python
  # 当前代码（有 bug）
  "WHERE owner_id IS NULL AND status = 'approved' AND job_position = ?"
  ```
  应为：
  ```python
  # 修复后
  "WHERE owner_id IS NULL AND status = 'approved' AND deleted_at IS NULL AND job_position = ?"
  ```
  这导致已软删除的 `question_bank` 记录被加载进 `existing_by_cat2`，成为匹配候选聚类。新题目可能匹配到已废弃的聚类，导致错误关联。

### 影响范围

| 维度 | BUG-001 | BUG-002 | BUG-003 | BUG-004 |
|------|---------|---------|---------|---------|
| **功能** | 重新分析 | 分析进度展示 | 分析进度展示 | 聚类准确性 |
| **用户** | 管理员 | 管理员 | 管理员 | 全部用户 |
| **数据** | 无（分析未写入） | 无 | 无 | 影响 question_bank 质量 |
| **频率** | 网络不稳定时触发 | 每次切换 Tab | 每次分析 | 每次有软删除数据时 |
