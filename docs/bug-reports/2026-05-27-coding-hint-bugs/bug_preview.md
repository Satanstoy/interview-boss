# Bug 预览报告

**日期:** 2026-05-27
**问题:** 手撕代码请求提示功能存在三个 bug
**严重程度:** High

## BUG-001: 请求提示输出重复

### 问题现象
点击"请求提示"后，反馈文本出现两次。同一段 hint 内容被展示两遍。

### 根本原因
流式发送逻辑缺陷：当 `---JSON---` 分隔符出现在某个 chunk 中间时，该 chunk 的内容（分隔符前的部分）已通过流式发送给前端。但解析后 `feedback_text` 又包含了同样的文本，如果 LLM 输出格式不符合预期（没输出分隔符），fallback 逻辑也会导致重复。

### 影响范围
- **功能:** 请求提示功能完全不可用，输出混乱
- **用户:** 所有使用手撕代码模块的用户

## BUG-002: hint 模式不应显示评分

### 问题现象
请求提示时也会显示评审评分面板，但用户要求只有"提交评审"才显示评分。

### 根本原因
前端没有区分 mode，`done` 事件中的 scores 总是被设置和显示。

## BUG-003: 提示不累积

### 问题现象
点击第二次"请求提示"时，第一次提示消失。用户期望按顺序保留所有提示。

### 根本原因
前端 `submitCode` 函数开头执行 `feedback.value = ''`，清空了之前的反馈。后端也没有发送累积的提示历史。
