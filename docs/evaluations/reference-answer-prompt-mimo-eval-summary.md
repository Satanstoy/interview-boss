# 公共参考答案 Prompt：MiMo 三轮评估总览

## 结论

三版候选 Prompt 都没有在 10 题小样本上达到统计显著提升，因此本次**不切换生产 `ANSWER_PROMPT`**。

最稳定、最有业务价值的发现是代码题语言遵从：生产旧版无条件要求 Python，面对“用 Java 实现 LRU Cache”仍输出 Python；候选版遵从 Java 后，该题在两轮实验中分别提升 `+0.70` 和 `+1.65`。候选版在真实性和约束遵从上也持续更好，但整体改写会损失 MiMo 的口述性。

## 三轮结果

| 轮次 | 改法 | 旧版 | 新版 | 差值 | 胜/负/平 | 符号检验 | 结论 |
|---|---|---:|---:|---:|---:|---:|---|
| V1 | 原则化重写、动态篇幅、按题型组织 | 8.61 | 8.92 | +0.31 | 4/1/5 | p=0.375 | 平均分最高，但未显著；口述性 -0.35 |
| V2 | 在 V1 上缩短篇幅、强化短句和无来源数字约束 | 8.70 | 8.60 | -0.10 | 1/4/5 | p=0.375 | 回退；口述性和易背性继续下降 |
| V3 | 回到旧版骨架，只做优先级、语言、安全和真实性增强 | 8.60 | 8.79 | +0.20 | 2/1/7 | p=1.000 | 准确/完整/约束更好，但口述性 -0.90 |

每轮都使用同一个 `mimo-v2.5-pro`：旧版和候选版各生成 10 份答案，再由同一模型做两轮匿名评审，第二轮交换 A/B。每轮约 40 次调用；不联网、不写数据库、不运行生成后 refine loop。

## 分维度观察

- **稳定改善**：准确性、完整性、真实性/约束遵从，尤其是题目指定编程语言时。
- **稳定风险**：原则化 Prompt 容易让 MiMo 写成长段说明文；生产旧版的“短列表 + 强标题限制”虽然繁琐，但确实更利于口述。
- **高价值单点修复**：把“代码题必须 Python”改成“题目指定语言则遵从，否则 Python”。
- **安全增强**：题目和联网资料统一视为不可信数据；无来源时不补公司、项目指标或精确性能数字。
- **不建议直接合入**：动态长篇幅、减少列表、用抽象原则替代现有排版硬约束。

## 建议的下一步

1. 生产 Prompt 只做编程语言遵从、安全边界和不编造精确数字三项窄改。
2. 再用 30–50 题、至少两次生成种子复验，并加入 2–3 位真人面试官盲评。
3. 把“口述性”拆成可观测指标：平均句长、连续长段数量、列表密度，再与真人偏好校准。
4. 只有成对胜率和真人偏好同时稳定后，再替换生产 Prompt。
