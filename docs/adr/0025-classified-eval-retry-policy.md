# ADR-0025: Eval Retry 按失败类型分类且禁止择优重试

**Status:** accepted

评测重试不是统一的“再运行一次”。每个失败 Attempt 必须先归类，Retry Policy 根据失败类型决定是否重试、重试哪一层和消耗哪个预算；重试预算属于不可变 Batch 上下文。

| 失败类型 | 默认处理 |
| --- | --- |
| Worker 崩溃、网络断开、Provider 临时错误、基础设施超时 | 在固定预算内重试同一个 Item，复用 planned seed 和 Batch 上下文 |
| Harness 契约失败、工具协议破坏、状态不可恢复 | 直接标记 Item 失败，不自动重试 |
| Agent 行为或质量不满足预期 | 作为真实评测结果保留，不自动重试 |
| Judge 临时错误或输出不可解析 | 只重试 Judge 阶段；已有 Agent 轨迹不重新执行 |

同一个 Item 如果存在多个成功 Attempt，系统不得选择分数最高者。默认接受第一个满足执行契约且成功提交的 Attempt；后续重复成功只作为异常诊断记录，不进入 Item 聚合。管理员需要重新验证时，必须发起新的 Eval Run 或扩展 Batch，而不是修改原 Attempt。

这样可以避免通过重复运行掩盖真实失败，或利用随机性人为抬高质量分数；同时保留基础设施故障的恢复能力。
