# ADR-0035: Eval Target 使用轻量隔离运行空间

**Status:** accepted

Eval Target 不直接使用真实用户数据和生产副作用运行。1.0 复用应用代码、Compose 网络和基础设施，但为评测提供独立的数据库或 namespace、测试身份、Artifact 根目录、工具夹具和配置边界。

最小隔离要求：

- Eval Worker 使用 `EVAL_MODE` 和评测专用数据路径/namespace；
- 对话、任务、工具写入只能落在评测空间；
- 评测不读取真实用户的简历、面试记录或生产任务；
- 需要外部服务时使用测试凭证、Mock 或受控 Fixture；
- 评测产物写入独立 Artifact 根目录；
- 不为 1.0 建设完整 staging 集群，但不得以“共用生产数据库”替代隔离。

评测空间的目的是保护数据边界和可重复性，不是复制全部生产拓扑。未来如果需要验证真实部署拓扑，可以新增更高等级的环境协议，但不能改变固定 Benchmark 的基础隔离契约。
