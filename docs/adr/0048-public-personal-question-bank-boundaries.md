# 公共题库与个人题库的领域边界

**Status: accepted (2026-08-20)**

公共题库和个人题库不是两个展示筛选，而是具有不同所有权、可见性、生命周期和写入范围的题库作用域。题目原始出现事实与题库聚类分开建模；同一题目出现可以关联到一个规范题库聚类，但一次聚类任务只能有一个明确的写入作用域。

## 决策

- 保留现有单表迁移的渐进路线，但在领域上明确区分 `Question Occurrence`、`Question Cluster`、关联关系和 `Public Promotion Request`；不把 `owner_id IS NULL` 继续作为唯一的公共语义。
- 个人上传命中已审核公共题时，公共题是唯一 canonical，不创建个人题副本。个人记录保留题目出现与公共聚类的关联，用户自己的答案、练习和复盘数据独立保存。
- 个人上传未命中公共题时，只能在当前用户的个人聚类池内聚类和写入；公共题库只能作为只读候选池，个人流水线不得写入公共聚类。
- 个人题升级公共题必须创建发布申请快照，进入公共匹配、聚类和审核队列。审核通过后，原个人聚类标记为已发布/重定向并保留原始事实和历史，不保留一个同时活跃的个人副本。
- 管理员默认不能查看其他用户的个人题。管理员只能查看用户主动提交的公共发布申请；特殊支持访问必须显式授权并留下审计记录。
- 聚类最终决策由一个持久化流水线负责。上传阶段不做一次决定、异步阶段再做一次独立决定；候选读取范围可以包含公共题和当前用户个人题，但最终 resolution 必须持久化且幂等。
- 聚类任务使用题目出现 ID、流水线版本和目标作用域构成幂等边界；重分析、清理和来源归属优先使用 `interview_id`/题目出现 ID，不能用裸 URL 推断所有权。
- 公共待审核内容只对提交者和审核人员可见；普通用户可以提交、查看状态和撤回，审核通过后才进入公共检索、统计、答案生成和公共聚类池。
- 个人题库重建不得隐式发布公共题；管理员将个人题并入公共题的旧路径必须被替换为显式发布操作。
- 本次范围不引入通用的“分享”授权、分享链接或协作副本；“个人题提交公共题库”统一建模为 `Public Promotion Request`，不是访问权转移。
- `PublicContributionRequest` 作为公共数据贡献申请的通用流程外壳，支持 `interview` 和 `jd` 两类来源；面经进入题目抽取/分类/公共聚类流水线，JD 进入岗位要求/技术栈/能力标签流水线，二者不共享最终领域实体。
- 面经贡献申请按批次审核、按题目产生处理结果；JD 默认按整份文档审核。JD 公共化默认只贡献脱敏后的结构化结果，不向普通用户公开原始 JD。
- 个人作用域的处理使用提交用户的模型配置；审核通过后的公共处理、公共聚类和公共规范答案使用全局模型配置；用户针对公共题生成自己的练习答案仍使用个人模型配置。
- 第一版同时覆盖面经和 JD 的公共化申请；二者共享申请、审核、权限、快照、队列和审计流程，但审核通过后分别进入面经题目流水线和 JD 结构化流水线。
- 当前版本的 JD 公共化是审核通过后生成结构化公共投影的确定性步骤，不额外调用 LLM，也不占用面经分析队列；未来若增加 JD 的 LLM 脱敏/标签增强，必须新增 `owner_id IS NULL` 的公共 JD 处理队列，不能复用个人 JD 配置。
- JD 以整份文档作为审核单元；管理员可以在进入公共处理队列前删除敏感字段或排除不适合贡献的结构化结果，不把 JD 拆成大量独立申请项。
- 公共任务在实际执行时读取当前生效的全局模型配置，并在任务/结果审计中记录实际使用的模型、Provider、API 格式和配置摘要；第一版不建立完整的模型配置版本注册表。
- 管理员使用统一的公共贡献审核台，通过 `source_type` 在面经/题库与 JD 之间筛选或切换；两类内容共用权限、状态和审核操作外壳，审核详情和后续流水线按类型展示。
- 公共化申请提交时生成不可变快照；用户之后修改个人面经或 JD 不改变正在审核的申请，新的内容必须通过撤回重提或新版本申请进入流程。
- 待审核申请可以撤回，处理中申请尽量取消未完成任务；已发布公共结果默认保留，只撤销与个人来源的关联。若结果只依赖被撤回来源，再进入管理员复核，不自动硬删除公共 canonical。
- 公共结果默认不展示用户身份、原始 URL、原始面经或原始 JD；公司、轮次、岗位等来源字段只有经管理员确认才可公开。JD 默认不公开公司、薪资、联系方式和原始描述。
- 管理员不修改原始快照，只能形成审核投影；第一版支持排除面经题目、删除 JD 敏感字段和修正明显结构化错误。审核投影发生实质变化时必须重新进入公共处理队列，并保留原始版本。
- 申请父级和处理子项分别记录状态；面经允许逐题部分成功，技术失败只重试失败子项。审核通过不等于公共可见，只有处理完成的子项进入 `published`，再参与公共检索、统计和答案生成。
- 旧的单题 pending 分享接口暂时保留兼容，但由统一审核台的“题库”标签展示；新上传入口不再允许普通用户通过 `target=share` 直接写入公共面经，必须先保留个人来源并创建本申请。

## 推荐的生命周期

```text
Question Occurrence
  ├─ 命中公共 Cluster → 关联公共 Cluster，不进入个人写入队列
  ├─ 命中个人 Cluster → 更新当前用户个人 Cluster
  └─ 未命中 → 创建当前用户个人 Cluster

Public Promotion Request
  → 公共候选匹配/聚类
  → 审核
  → 合并到已有公共 Cluster 或创建新的公共 Cluster
```

## 结果与代价

公共候选可以被个人上传流程读取，但读取范围不再决定写入范围；所有写入路径必须显式携带 target scope。这样可以消除同步预匹配与异步聚类的重复决策，也能防止个人聚类新记录因默认 `owner_id=NULL` 落入公共题库。

这项设计需要新增题目出现到聚类的持久关联、发布申请和聚类决策任务的幂等约束，并逐步迁移现有 JSON 来源投影和 URL 级关联。
