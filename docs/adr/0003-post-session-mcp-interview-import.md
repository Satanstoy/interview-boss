# ADR-003: MCP 面试记录采用结束后批量导入

**Status:** accepted

MCP 第一阶段不尝试被动实时监听 ChatGPT 对话，而是在外部面试结束后提交完整面试记录；记录过长时允许分块传输，完成后由 InterviewBoss 统一解析、分析并呈现为原生兼容的面试记录。这样可以保证导入记录的完整性、支持失败重试和幂等处理，同时保留外部来源，避免把外部内容误记为 InterviewBoss 原生事件。

MCP 通过五步导入生命周期暴露能力：创建导入任务、上传导入分块、完成导入、查询导入状态、重试导入分析。外部代理必须复用同一个导入任务，不得在失败后无条件创建新任务。

导入分析完成后，来源记录保持封存；用户如需继续练习，创建与来源记录关联的新的 InterviewBoss 原生面试，不把外部历史和新的原生回合混入同一状态流。

导入草稿和分块属于独立的暂存域；只有分析成功后才执行原生记录投影，写入现有面试会话、消息和事件模型，以复用原生面试空间的读取与续接能力。

创建导入任务使用外部请求标识保证幂等：同一请求标识返回原任务，不重复创建；不同请求标识即使内容相同也允许产生新的面试经历。

MCP 同时提供当前用户面试记录的摘要列表、单条记录读取、报告读取和面试续接入口；默认不返回完整原始记录，完整原文必须显式请求。

每条导入面试记录保存独立的面试上下文快照，包括目标岗位、公司、面试轮次、招聘季、JD 和简历版本；后续用户资料变化不改写历史记录的分析依据。

同一记录的重新分析生成新的报告版本，最新成功版本作为当前官方报告；失败分析不会覆盖已有成功版本，GPT 提交的外部分析独立保留。

导入分析使用单轮回答评估和面试报告评分两层结果：单轮结果保存各维度、证据、缺失点和后续动作，面试报告基于多轮证据、题目难度、能力覆盖和岗位要求综合形成，不采用单轮分数的简单平均。

结构化面试回合是分析的主依据，完整原始面试记录是不可变证据；两者都支持分块传输。导入分块使用稳定编号和内容 hash，允许乱序到达；相同编号和相同 hash 的重复提交幂等成功，相同编号但内容不同则报告为不可恢复冲突。上传失败时，MCP 返回机器可读的错误码、可重试标记、导入任务标识和失败分块信息，让外部代理只重试失败部分。导入任务独立于 MCP session 持久化，默认至少保留 24 小时，以支持断线恢复；导入任务和正式记录绑定当前认证用户，不接受客户端指定 user_id。完成上传只触发异步导入分析并返回处理中状态；分析完成且成功后才转为正式面试记录。分析失败时保留已接收内容，只重试导入分析，不要求外部客户端重新上传；不可恢复失败则保留草稿并返回明确原因。GPT 提供的题目 ID 只是候选关联，InterviewBoss 后端必须校验题目存在性、权限和题面一致性；无法可靠关联的问题作为外部问题保留在当前记录中，不写入公共题库。GPT 随记录提交的评分和总结作为外部分析保存，但不覆盖 InterviewBoss 官方分析。导入记录复用原生面试记录和报告能力，并可参与面试题目去重，但不会自动写入独立练习历史。面试表现统计与练习题统计保持分离。导入记录与原生记录共享用户的面试空间和查看体验，但原始记录不可变，评分、阶段和报告由 InterviewBoss 基于导入内容重新生成；正式记录随用户保留并在删除时级联删除，导入草稿超过 24 小时未完成则自动过期，完整原文不写入普通日志或工具错误响应。
