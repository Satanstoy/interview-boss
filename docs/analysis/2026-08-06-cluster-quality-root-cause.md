# 聚类数据质量根因分析（代表题 / 误合并 / 重复变体）

**日期**: 2026-08-06
**来源**: representative_quality_eval（15 聚类/79 变体 mimo 核验）+ mock_incremental_eval + 聚类实验 R1-R3

## 数据事实（抽样评估）

| 指标 | 数值 |
|------|------|
| 代表题涵盖全部变体 | 14/15（93%）——"选最清晰题面"机制基本可用 |
| 误合并变体（考察点不同被并入） | 13/79（16.5%） |
| 重复变体（同题多表述） | 17/79（21.5%） |
| 代表题质量差案例 | 6039"工作流和agent区别"（过于简略，4 变体 3 个误并入） |

## 根因拆解（三层，非"聚类质量+pompt"两因素）

### 1. 误合并（16.5%）→ LLM 边界判断能力 → 验证层覆盖不全
- 现象：5872 混入"研究生方向"、5943 混入宽泛"召回机制"题、6019 混入"评测目标"题
- 证据：实验 R1→R2 收紧 prompt 无效（42→40 合并，偏宽仍在）；R3 验证层把偏宽从 4-5 条降到 2 条
- 根因：**单次 LLM 判断对"主题相近但考察点不同"的边界题不可靠**；生产 `_validate_merges` 只对"中置信/保守"匹配启用，**高置信直通无验证**——覆盖不全

### 2. 重复变体（21.5%）→ 变体归一化工程缺失
- 现象："rag流程"×5、"为什么用mcp"×2（同一面试追问）
- 根因：合并判断正确（确实同题），但写库 `writer._build_new_entry` 只做**完全文本去重**（`if q not in original_questions`），相似表述不去重
- 与聚类质量/prompt 无关，纯工程缺口

### 3. 代表题选择弱（6039 类）→ prompt 标准不足
- 现象：代表题"工作流和agent区别"过于简略，未涵盖变体中的深层对比
- 根因：CLUSTER_NEW_PROMPT 只要求"表述最清晰的代表题"，缺"最完整/规范"维度；无"生成规范版"机制（实验的 cluster_label 标签摘要可补，P2 已落库但未用于代表题）

## 修复路线（按优先级）

| # | 修复 | 药方 | 预估收益 |
|---|------|------|---------|
| 1 | **验证层全量覆盖**：`_validate_merges` 对高置信匹配也做（或抽样）二次验证；或引入实验验证层（两轮布尔一致） | 实验 R3 已验证 | 误合并 16.5% → <5% |
| 2 | **变体归一化**：写库前对 oq 变体做规范化相似去重（`_normalize_question_text` 子串/包含） | 工程 | 重复 21.5% → <5% |
| 3 | **代表题选择升级**：prompt 加"完整度"标准；对简略代表题用 cluster_label 生成规范版（实验验证标签质量优） | prompt + 已有标签机制 | 6039 类案例消除 |

## 与实验结论的一致性

- 三条修复与聚类实验结论完全对齐：验证层（R3 最佳配置）、文本预筛（零成本确定性）、标签摘要（LLM-MemCluster 模式）
- 已落生产：cluster_label 列 + 标签生成（P2）、异步化（P3）、listwise rerank（P1a）
- 未落生产：验证层全量覆盖、变体归一化、代表题选择升级
