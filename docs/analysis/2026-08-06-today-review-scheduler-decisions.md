# 今日复习调度系统 — 最终决策报告

> 日期：2026-08-06
> 范围：刷题产品形态 + 招聘季调度算法（紧迫度/间隔/队列）+ 已掌握题抽查机制
> 依据：行业调研（Anki/FSRS 社区、记忆科学文献、求职产品）+ 真实题库数据实验

## 1. 产品形态：删抽测、单一主入口

**问题**：产品有"题目抽测"（/mock-interview）和"刷题"（/practice）两个独立入口，用户提议合并并质疑"双模式"。

**调查发现**：
- 抽测页（随机批量抽题 + AI 评估）与刷题页的"自测一下"调用**同一个 `POST /api/evaluate-answer` 接口**、同一套评估展示、同一个练习历史，功能重复约 90%
- 抽测是"随机批测、答完即弃"——**不进任何复习调度**，信息不沉淀
- 竞品验证（面试智练：8 种"模式"本质是同一套闪卡的筛选条件，主入口就是"今日复习"；不背面试：首页主入口是"每日弱题"）：**单一"今日复习"入口是这类产品的正确形态**

**结论**：删抽测独立页；刷题页默认进入"今日复习"队列；题单选择器（全部/收藏/自定义）降级为次要入口。不做"背题卡/刷题"双模式（模式切换是伪需求）。

---

## 2. 紧迫度模型：机会脉冲（无 DDL）

**问题**：原设计用"距下一个里程碑的线性映射"驱动紧迫度，且窗口关闭（window_close）时做"截止前压缩复习"。用户指出：**秋招后还有春招、春招后还有社招，不存在真正的 DDL**。

**调研依据**：
- 招聘年度周期（applywave 2026 数据 + 中国校招时间线）：1-3 月社招旺季+春招、9-11 月秋招+社招次高峰、6-8 月淡季但秋招提前批预热——**全年是连续的机会流，不是离散截止日**
- 记忆科学（LessWrong 2025 "Notes on spaced repetition scheduling"）：SR 算法核心是"现在学 vs 以后学的期望值"，**无 DDL 时只需持续保持**；Anki 的 deadline 压缩（exam mode）只适用于确定考试日期
- 求职产品（Reqon/JobJam）："持续轨道"思维，机会按强度排序而非按截止日

**模型**：

```
紧迫度(t) = clamp(base + Σ 窗口脉冲(t) + 节奏偏移, 0, 1)
base = 0.2（社招/日常实习随时可能面试，复习永不停）
窗口脉冲 = 高峰前 45 天线性爬升到振幅 → 高峰后 45 天衰减回 base
```

**连带简化**：原设计的 deadline 压缩（Task 3 实现的"窗口关闭前保证复习一次"）**删除**——那是 Anki 针对确定考试日期的做法，在连续机会模型里是过度设计。间隔只受 urgency 缩放（≤40%）影响。

---

## 3. 调度参数：base=0.2 / amp=0.6 / 窗宽45天

**实验**（2027 届全年 546 天曲线，真实题库 321 道）：

| 参数 | 高压天数(≥0.6) | 中压(0.3-0.6) | 峰值 | 评估 |
|---|---|---|---|---|
| base 0.2 amp 0.6 窗45d | 49 | 218 | 0.80 | ✅ **推荐**：高峰 0.8、间歇 0.2 |
| 窗 30d | 33 | 151 | 0.80 | 爬升突变，紧迫感跳跃 |
| 窗 60d | 84 | 254 | 0.80 | 高压期过长，整季紧绷 |
| amp 0.5 | 22 | 235 | 0.70 | 冲刺感弱 |
| amp 0.7 | 84 | 194 | 0.90 | 峰值过激 |
| base 0.15 | 32 | 205 | 0.75 | 间歇偏消极 |
| base 0.3 | 111 | 435 | 0.90 | 全年无低压，疲劳 ❌ |

**输入敏感性验证**（日期 × 画像 × 紧迫度→间隔三组实验）：
- 3 月入场：0.48→0.59→0.46→0.33→0.20（暑期实习季，合理）
- 8 月入场（今天）：0.43→0.47→0.42→0.52→0.65→0.75（持续爬升，合理）
- 12 月入场：全 0.20（间歇期从容，春招前 2 月自动爬升，合理）
- 毕业过渡：恒 0.20（社招 base，正确退化）
- 间隔调制单调正确：urgency 0.80 → 间隔 -32%；0.20 → -8%

## 4. 用户节奏档位：±0.3 偏移

**理由**：
- 日历模型捕捉不了主观状态：用户可能提前被约面（需要加压）、投了没回音（松弛）、拿了 offer（保持手感）
- 行业参照：FSRS 的 desired retention 就是同类的用户强度旋钮
- 3 档（轻松/标准/冲刺）零认知负担，默认"标准"时行为与纯自动完全一致

**公式**：`紧迫度 = clamp(base + 脉冲 + 偏移, 0, 1)`，偏移 ∈ {-0.3, 0, +0.3}
- 秋招高峰 0.8 + 冲刺 → 1.0；+ 轻松 → 0.5
- 淡季 0.2 + 冲刺 → 0.5（用户感知机会在来）

---

## 5. 届次时间线：自动流转，零配置

**问题**：原设计按"批次"存偏好（用户选秋招就只有秋招的里程碑），秋招结束后紧迫度归零，**必须手动改设置才能进入春招**。

**改动**：`get_season_milestones(year)` 返回全年 8 个里程碑（暑期实习 3 + 秋招 3 + 春招 2）；紧迫度天然"取下一个未来里程碑"，自动完成：

```
2026-08-05 → 秋招提前批高峰（紧迫 0.43）→ 10-15 正式批高峰（0.80）
2026-12-31 → 秋招结束 → 春招主批高峰 2027-04-15（间歇期 0.20）
2027-02-15 → 距春招 59 天 → 紧迫自动爬升
2027-06-30 → 毕业 → 社招 base 0.20（持续准备）
```

用户只设置"届次"（或跳过=社招模式），批次自动跟随展示。实验已验证三个入场时间 + 毕业过渡的输出都合理。

## 6. 已掌握题抽查：固定 30 天（数据推翻分级方案）

**问题**：题库仅 321 道，用户 1-3 个月学完后 SM-2-lite 间隔拉长，**73% 的天复习量 < 5 题**——"没题可刷"是比参数更严重的留存杀手。

**调研锚点**：Cepeda 2008（长期保持最优检查间隔 3-5 周≈30 天）、Rohrer & Pashler 2007（6 个月 retention → 最优 1 个月）、Bahrick（30 天间隔显著）。**多个独立研究交叉指向 30 天**。

**周期实验**（321 题 × 546 天，遗忘模型 R=exp(-d/S)，S∈{150,250} 双组）：

| 组合 | 每天 med/p90 | 回炉率 S=150 | 回炉率 S=250 | 检查时平均 R |
|---|---|---|---|---|
| **固定 30 天** | 7 / 11 | **0.6%** | **0.0%** | 0.95 / 0.97 |
| 分级 60/30/14 | 7 / 17 | 8.2% | 0.1% | 0.73 |
| 分级 90/45/21 | 6 / 14 | **16.2%** | 2.7% | 0.63 |
| 分级 45/21/7 | 11 / 20 | 3.5% | 0.0% | 0.83 |

**为什么分级（easy 60 / hard 14）被否定**：
- easy→60 天：S=150 的用户检查时 R 掉到 0.73（低于 Bjork 阈值 0.7-0.8 边缘），回炉率 8.2%
- hard→14 天：记忆未充分恢复时重复查，反而提高失败概率
- Cepeda 的"间隔过长成本小"结论仅适用于**有确定考试日期**的场景；面试是**随机抽查**，答不上 = 当场失败，成本函数不同，保持率优先于效率

**最终规则**（最简单且数据最优）：
```
抽查队列 = state='mastered' AND next_review_at <= now
easy/good/hard → 统一重置 next_review_at = now + 30 天
again → proficiency-1、state='review'、29 分钟后再复习（降级回炉，回到密集调度）
```
321 题全掌握时每天 ≈ 7-11 道抽查，容量 30 内宽松；规模随掌握数自动增减（30 天循环天然自平衡）。

## 7. 容量分配：新题 = 容量 − due − 抽查

**依据**（Anki 共识 + 队列演化模拟）：
- Anki/FSRS 社区铁律：**复习永不设上限拦截**，新题是未来工作量的杠杆（约 1:10），复习多时自动少开新题
- 模拟验证：新题预算 = 剩余容量时，容量 30 下队列稳定（超载天 1-2 天）；用户 1-3 个月学完题库是规模问题，不是容量策略问题

**规则**：`新题预算 = max(0, 容量 − 到期复习 − 抽查)`——复习和抽查优先，新题让位。

---

## 8. 实验限制与风险

1. **真实库复习记录为空**（51 用户、0 条 user_question_review）：队列行为用从零模拟验证，未经过真实用户数据校准
2. **遗忘模型为理论近似**（指数遗忘 + 评分概率函数），参数（S=150/250）是估计值；抽查周期上线后可用真实评分数据校准
3. **紧迫度对队列规模的杠杆有限**（容量饱和时主要由容量决定），参数影响的是"曲线形态"而非"做题量"——这是设计意图（数量是输出，不是输入）
4. **题库规模是系统级瓶颈**：321 道题（高频≥3 仅 39 道）在抽查机制上线后仍建议扩充（抽查保手感治标，题库扩充治本）

## 附：被否决的方案

| 方案 | 否决理由 |
|---|---|
| 双模式（背题卡/刷题模式） | 模式切换是伪需求，单一闪卡流 + 卡内次级动作已覆盖 |
| 固定日历表（第1/3/7/15天式安排） | Anki/FSRS 社区共识：固定表不如自适应调度 |
| 频率直接压缩间隔（高频多背） | 挤占其他题复习时间，间隔效应边际收益低；频率只管排序和引入顺序 |
| 紧迫度 = 距单一批次里程碑的线性映射 | 无法表达秋招→春招→社招连续性（单批次快照） |
| deadline 截止前压缩复习 | 无真实 DDL，过度设计（Anki exam mode 只适用确定考试日） |
| 抽查分级周期（60/30/14） | 实验否定：回炉率 8-16%，R 跌破阈值 |
| base=0.3 全年紧迫 | 实验否定：全年无低压天，用户疲劳 |
