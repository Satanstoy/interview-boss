## 确认的问题、影响与修复

## 建议的概念和处理流

明确分开四类实体：面经原文、提取的原始题、规范题/聚类、发布审核申请。另有任务、任务步骤和费用账本。分类是标签体系；聚类是同义题关系；私人/公共是数据可见范围；审核和计算完成度是独立状态。

个人上传：保存私人原文→提取/分类→私人聚类或引用公共规范题→可选私人答案。公共引用带私人owner，不修改公共题的来源和频次。无公共匹配允许保留独立私人题，分类映射带taxonomy_version。

普通用户贡献：私人原文→明确提交发布快照→管理员审查（隐私、版权、内容质量）→批准→公共提取/重新匹配/聚类→公共答案。拒绝不影响私人记录。审核前调用若允许系统补贴，必须显式预算；不能由Key静默fallback决定。个人处理可以使用个人Key，批准后的公共处理使用系统服务凭据。

管理员直接公共导入可以是显式授权的快捷流程，但需可见目标、系统费用说明及审计记录。管理员选择“私人”仍走私人归属；角色不应偷偷改变上传目标。

服务端快照是真实状态，SSE只通知变化：先GET当前快照，再订阅带revision的事件；断线重连按游标补发，或拉新快照覆盖。事件日志与业务副作用都要幂等。前端断线不终止后台任务，也不应宣告成功或失败。

## 用户确认的首要产品原则：像浏览器下载任务一样可恢复

每次被服务端接受的上传都有持久任务记录，刷新、关闭页面、断网或失败后仍可找到；完成任务也保留结果入口，不以5秒消失的浮层作为唯一记录。任务中心显示文件/标题、目标库、阶段、已完成量、错误原因和结果。

恢复按钮必须推进同一业务任务：网络/限流可自动退避并允许手动重试；401显示“修复模型配置后继续”；权限/输入错误解释需修正的条件；聚类或答案失败只重跑失败步骤。保留已保存原文、提取结果和明细，使用幂等键防双击/多端重复恢复。失败不等于回滚全部成果，也不等于再次上传。

暂停/取消是独立能力，需要定义停止边界、在途调用和已保存结果的处置，不能仅断开SSE就宣称暂停。HTTP校验400发生在任务接受之前，导入页面须保留草稿和错误，修正后重新提交；若未来要统一显示为任务，先建立上传会话再校验。

以此作为第一验收条件：任务被接受后，用户随时能知道它在哪里、做到哪一步、为什么停住、下一步如何继续，而且恢复不产生重复记录或不必要的重复调用。
