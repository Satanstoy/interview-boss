# Chatbot 面试质量评估 — 优化后 Prompt

**日期**: 2026-05-24
**评估人**: Claude Code (自动化测试)
**测试方法**: 使用施杰真实简历，3 种不同回答风格进行模拟面试

## 测试概览

| 面试 | 风格 | 轮次数 | 主题覆盖 | 状态 |
|------|------|--------|---------|------|
| #1 | 简洁型 | 10 轮 | 项目深挖 + 八股 + 算法 | ✅ 完成 |
| #2 | 详细型 | 5 轮 | 项目深挖 + 八股 | ⚠️ Token 过期中断 |
| #3 | 不确定型 | 12 轮 | 项目深挖 + 八股 + 算法 + 边界追问 | ✅ 完成 |

## 优化效果评估

### 1. 穿插式节奏 ✅ 显著改善

**Before**: 项目深挖 → 八股 → 算法，界限分明
**After**: 自然穿插，节奏真实

面试 #3 示例:
- R1: 自我介绍
- R2-R6: GLEAR 项目深挖 (4 层追问)
- R7-R8: RAG 八股 + HNSW 参数
- R9: 进程/线程八股
- R10-R11: LRU Cache 算法 (含代码 + 边界追问)
- R12: 回到项目 schema 设计

**评价**: 穿插非常自然，和真实字节/阿里面试节奏一致。

### 2. 深度追问 ✅ 显著改善

**Before**: 1-2 层追问后就换话题
**After**: 3-5 层追问，直到摸清候选人真实水平

面试 #3 GLEAR 项目追问链:
1. 知识图谱构建细节 (技术栈? 流程?)
2. 为什么选 LLM 而非 BERT-NER? (对比实验? 准确率?)
3. 你在项目中具体负责什么?
4. 融合机制具体怎么设计? (并行 vs 级联?)
5. 为什么不用 cross-encoder reranking?

**评价**: 追问深度接近真实大厂面试官水平。

### 3. 冷峻务实风格 ✅ 显著改善

**Before**: "很好"、"不错"、"回答得挺清楚"
**After**: 无鼓励语言，直接追问或转换话题

面试 #3 实际表现:
- "你提到GLEAR框架构建了一个34万规模的异构法律知识图谱。我想先问下..."
- "你提到用LLM抽取实体关系，但没说清楚为什么选这个方案。"
- "思路没问题，但你只说了思路，没写代码。现在手写出来。"
- "空cache时put没有问题，你的代码逻辑是通的。那如果capacity设为0呢？"

**评价**: 完全消除了鼓励性语言，风格冷峻务实。

### 4. 算法题追问 ✅ 新增能力

**Before**: 算法题只问思路，不要求写代码
**After**: 要求写代码 + 追问边界情况

面试 #3 LRU Cache 流程:
1. "手写一个LRU Cache，说一下思路，然后写出关键代码。"
2. (候选人只说了思路) "思路没问题，但你只说了思路，没写代码。现在手写出来。"
3. (候选人写了代码) "空cache时put没有问题。那如果capacity设为0呢？"

**评价**: 要求写代码 + 追问边界，非常真实的面试体验。

### 5. 参考题目使用 ✅ 正常

AI 正确使用了 `参考题目 (N)` 按钮，从题库中检索相关题目作为追问方向。

## 候选人回答风格测试

### 简洁型 (面试 #1)
- AI 行为: 简洁回答后 AI 追问更多细节
- 效果: ✅ 正确地对简短回答进行了追问

### 不确定型 (面试 #3)
- 候选人使用: "好像是"、"大概"、"我记得"、"不太确定"
- AI 行为: 没有因为不确定就放过，继续追问细节
- 效果: ✅ 真实面试中面试官也会这样处理

## 发现的问题

### 1. Token 过期导致面试中断
- 面试 #2 在第 5 轮时 JWT token 过期 (401)
- 需要刷新页面重新认证
- **建议**: 前端增加 token 自动刷新机制

### 2. API 偶发错误
- 面试 #12 轮出现 "发送消息时出现错误"
- 可能是 LLM API 超时或限流
- **建议**: 增加重试机制

## 结论

优化后的 prompt **显著提升了面试质量**，面试官行为接近字节/阿里/腾讯真实面试官水平:
- 穿插式节奏 ✅
- 3-5 层深度追问 ✅
- 冷峻务实风格 ✅
- 算法题要求写代码 + 边界追问 ✅

**整体评分: 9/10** (优化前 6/10)
