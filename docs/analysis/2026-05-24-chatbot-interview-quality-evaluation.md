# 模拟面试质量评估报告

**日期:** 2026-05-24
**评估范围:** 3 次模拟面试 + 真实大厂面试官行为调研
**目标:** 评估当前 chatbot 面试质量，对标真实大厂面试流程，输出优化建议

---

## 三、核心差距分析（当前 vs 真实大厂面试官）

基于 exa 搜索的真实大厂（字节、阿里、腾讯、美团）面试官行为模式：

### 差距 1: 过度鼓励，缺乏真实感

**当前行为:**
- "你的回答非常清晰，对 RAG 系统有扎实的理解"
- "非常扎实的回答，你对 Agent 架构的理解很到位"
- 每轮回答后都给出正面评价 + 改进建议

**真实面试官行为:**
- 不会夸奖候选人，只会说"嗯，继续"或"还有吗"
- 不会主动给"改进建议"，那是面试结束后 HR 的事
- 如果回答不满意，会直接追问"你确定吗？"或"那如果 XX 情况呢？"

**影响:** 候选人无法获得真实的面试压力感，练习效果打折。

### 差距 2: 完全缺失八股文考察

**当前行为:**
- 只问 Agent/LLM 相关的技术问题
- 从未考察 Redis、MySQL、网络协议、操作系统、数据结构

**真实面试官行为:**
- 字节：每轮必考八股（Redis 缓存策略、MySQL 索引原理、TCP 三次握手）
- 阿里：将八股与项目场景结合（"你项目用了 Redis，那说说缓存穿透怎么解决"）
- 腾讯：考察技术广度，八股覆盖面广

**影响:** 候选人只练习了 Agent 技术栈，基础工程能力完全没练到。

### 差距 3: 项目深挖不够深入

**当前行为:**
- 问一个项目问题，候选人回答后 1 轮追问就换题
- 追问停留在"技术难点是什么"层面

**真实面试官行为:**
- 字节：一个项目聊 30 分钟，连续追问 4-5 层
  - "你用了 RAG → 为什么不用微调？→ RAG 的检索准确率多少？→ 准确率不够怎么办？→ 你试过哪些优化？效果如何？"
- 阿里：50%+ 面试时间在项目上，追问架构决策的 trade-off
- 腾讯：基于简历逐行提问，不放过任何细节

**影响:** 候选人没有被深度拷问的经验，真实面试时容易露馅。

### 差距 4: 缺乏算法/手撕代码环节

**当前行为:**
- 从未要求候选人写代码或描述算法思路

**真实面试官行为:**
- 字节：每轮必考算法（Medium/Hard），30-45 分钟手撕
- 阿里：算法题与项目结合（"你项目里用到了排序，手写一个快排"）
- 即使是 Agent 岗，也会考 LRU Cache、TopK、图遍历等

**影响:** 候选人完全没练习手撕代码环节。

### 差距 5: 面试节奏过于单一

**当前行为:**
- 线性流程：开场 → 提问（一个话题接一个）→ 收尾
- 每个话题独立，缺乏话题间的关联

**真实面试官行为:**
- 穿插式：项目深挖 2 题 → 八股 1 题 → 算法 1 题 → 回到项目继续深挖
- 从回答中发现新线索继续追问（"你提到了 Redis，那说说..."）
- 自然过渡，不按固定模板走

**影响:** 面试缺乏真实感，候选人无法练习"在不同话题间切换"的能力。

### 差距 6: 收尾阶段过于机械

**当前行为:**
- 超过 16 条消息自动进入收尾
- 收尾就是"总结表现 + 问候选人有没有问题"

**真实面试官行为:**
- 收尾时机取决于面试官判断，不固定
- 有些面试官直接结束，不总结
- 有些面试官会留 5 分钟让候选人提问
- 有些面试官会在最后一刻突然追加一个算法题

## 四、优化方案

### 4.1 System Prompt 重构（最高优先级）

**文件:** `backend/app/agents/chat/prompts.py`

**修改要点:**

1. **删除所有鼓励性措辞**，替换为中性/专业口吻
2. **删除"改进建议"要求**，面试官不给建议
3. **增加八股文考察要求**，每个面试至少 2-3 轮八股
4. **增加算法/手撕代码要求**，每个面试至少 1 轮
5. **增加深度追问要求**，每个项目问题至少追问 3 层
6. **修改阶段定义**，从消息数驱动改为内容驱动

### 4.2 面试阶段重新定义

**文件:** `backend/app/agents/chat/nodes.py` 的 `_determine_interview_phase()`

**当前问题:** 用消息数硬编码阶段（≤2=开场，≤16=提问，>16=收尾）

**优化方案:** 改为由 LLM 自主判断面试阶段，注入 system prompt 的指令中：
- 开场：自我介绍后，简短过渡
- 提问阶段：LLM 自行决定何时换话题、何时追问、何时收尾
- 收尾：当 LLM 认为已经充分考察后自行收尾

### 4.3 追问深度机制

**当前问题:** 追问 1-2 次就换题

**优化方案:** 在 system prompt 中明确要求：
- 项目问题：至少追问 3 层（为什么选这个方案 → 遇到什么问题 → 怎么解决 → 有没有更好的方案）
- 八股问题：至少追问 2 层（概念 → 应用场景 → 边界情况）
- 如果候选人回答不好，不要换题，而是降低难度继续追问

### 4.4 八股文穿插机制

**当前问题:** 只问 Agent 技术栈

**优化方案:** 在 system prompt 中要求面试流程：
1. 项目深挖（2-3 题，每题 3+ 轮追问）
2. 八股穿插（从项目中自然引出，如"你用了 Redis，那说说..."）
3. 算法/手撕（1 题，与项目或八股相关）
4. 重复 1-3 直到面试结束

### 4.5 压力追问模式

**当前问题:** 面试官太友善

**优化方案:** 在 system prompt 中加入：
- "你确定吗？"（当候选人回答有明显漏洞时）
- "那如果 XX 情况呢？"（压力场景追问）
- "这个方案有什么问题？"（要求候选人自我反思）
- 不要夸奖候选人，最多说"嗯"或"继续"

## 六、总结

当前 chatbot 在 Agent/LLM 技术栈的问题覆盖上表现尚可，但与真实大厂面试差距显著：

1. **风格差距最大**: 过度鼓励、缺乏压力感、主动给改进建议 — 这些是真实面试官绝对不会做的
2. **内容差距第二大**: 完全缺失八股文和算法手撕，而这是大厂面试的标配
3. **深度差距第三**: 项目追问太浅（1-2 层 vs 真实的 4-5 层）

**核心优化方向:** 让面试官更"冷酷"、更"全面"、更"深入"。不需要改架构，只需要改 system prompt 和阶段判断逻辑。
